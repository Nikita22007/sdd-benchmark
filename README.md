# sdd-bench

Небольшой стенд для сравнения стратегий работы с инженерной задачей: «сначала спецификация» и «сразу код».
Всё детерминировано и работает без моделей и сети, поэтому годится для быстрой проверки механики и для CI.

## Быстрый старт

```powershell
python -m bench.cli run --scenario scenarios/sum-bytes.toml --agent frugal
python -m bench.cli run --scenario scenarios/normalize-name.toml --agent greedy
python -m bench.cli report
```

Команда `run` пишет JSON в `results/`, код возврата `0` — проверка пройдена, `1` — нет.
`report` сводит все прогоны в таблицу по агентам.

## Как устроено

| Каталог | Назначение |
|---|---|
| `bench/agents.py` | детерминированные агенты: `frugal`, `greedy`, `sloppy` |
| `bench/runner.py` | загрузка сценария, запуск агента, запись результата |
| `bench/report.py` | сводка по каталогу `results/` |
| `scenarios/*.toml` | сценарий: имя, цель, фрагмент проверки |
| `tests/` | тесты без моделей |

Сценарий — это TOML с тремя полями: `name`, `goal` (то, что должен выдать агент) и `check`
(подстрока, наличие которой считается успехом). Такая схема намеренно примитивна: стенд
проверяет не качество кода, а саму механику запуска и учёта.

## Ограничения

- Агенты не вызывают модель: `frugal` выдаёт цель как есть, `greedy` дописывает комментарии,
  `sloppy` возвращает заглушку. Это нужно, чтобы проверять обвязку бесплатно.
- Метрика «токенов» здесь — длина выхода в символах, а не реальный расход.
- Никакой изоляции процессов нет: сценарии исполняются в текущем каталоге.
