# SDD Benchmark — прототип

Ядро запускает пакет подхода на копии репозитория из пакета задачи, добавляя запрос и готовый SDD-контекст, затем запускает отдельную проверку. Требуется Python 3. Запуск из этой папки:

```powershell
python benchmark.py --task catalog-search --approach demo
python benchmark.py --task catalog-search --approach noop
```

Первый прогон должен пройти, второй — завершиться ошибкой проверки. Результат, рабочая копия и логи сохраняются в `runs/<run_id>/`. Код возврата 0 означает успех, 1 — неуспех прогона, 2 — ошибка конфигурации.

Задача: `tasks/<имя>/task.json`, `project/`, `context/`, `request.md`, `evaluation/`. `evaluation_command` — массив аргументов; проверке доступен путь к рабочей копии в `BENCH_WORKSPACE`. Подход: `approaches/<имя>/approach.json`, `instructions.md`, команда в поле `command`. Процессу передаются переменные `BENCH_WORKSPACE`, `BENCH_TASK`, `BENCH_CONTEXT`, `BENCH_APPROACH`, `BENCH_PYTHON`. В командах доступны замены `{python}`, `{task}`, `{approach}`; оболочка не используется.

Демонстрационный исполнитель не является OpenSpec или агентом: он проверяет проводку. Реальный адаптер OpenSpec, модель-проверяльщик, токены, разметка фаз и полноценная изоляция ещё не реализованы. Процессы запускаются с правами текущего пользователя: отдельная рабочая копия не защищает закрытые тесты от чтения или изменения. Запускайте только доверенные команды.
