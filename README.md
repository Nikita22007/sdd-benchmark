# SDD Benchmark — прототип

Ядро независимо выбирает пакет задачи, SDD-подход и харнес. Python 3, без сторонних Python-зависимостей.

```powershell
python benchmark.py --task catalog-search --approach demo --harness demo
python benchmark.py --task catalog-search --approach demo --harness noop
```

Первый запуск проходит тесты, второй демонстрирует ошибку. Результат, рабочая копия и логи сохраняются в `runs/<run_id>/`. Код возврата: 0 — успех, 1 — неуспех прогона, 2 — ошибка конфигурации.

Пакет задачи `tasks/<имя>/` включает `task.json`, исходный `project/`, SDD-контекст `context/`, `request.md` и независимую `evaluation/`. Проверка задаётся массивом аргументов `evaluation_command`. Пакет подхода `approaches/<имя>/` содержит `approach.json`, `instructions.md` и опциональную команду `setup_command`. Пакет харнеса `harnesses/<имя>/` содержит `harness.json` с `command` и `requires_model`. В командах поддерживаются `{python}`, `{task}`, `{approach}`, `{harness}`. Доступны переменные `BENCH_WORKSPACE`, `BENCH_TASK`, `BENCH_CONTEXT`, `BENCH_APPROACH`, `BENCH_PYTHON`.

Харнесы, для которых `requires_model` истинно или не задано, не запускаются без явного `--allow-model`. Этот флаг не ограничивает расход токенов. Демо-харнес детерминирован и не является моделью. Доступен пакет `openspec` и харнес `codex`, но их совместная работа пока не подтверждена: Windows-песочница Codex вернула ошибку доступа. Настройка OpenSpec требует Node.js, npx и доступа к npm. JSONL Codex сохраняется в `agent/stdout.bin`.

Исполнители работают с правами текущего пользователя: рабочая копия не защищает закрытые тесты от доступа или изменения. Полноценная изоляция, лимиты токенов и модель-проверяльщик ещё не реализованы. Запускайте только доверенные команды.

Доступная телеметрия сохраняется в `telemetry.json`. Для Codex отражается usage на уровне `turn.completed` с пометками `reported`/`missing`; расход отдельных запросов, фазы и стоимость остаются неизвестными. Исходный JSONL сохраняется целиком. Проверка парсера без моделей: `python -m unittest discover -s tests`.

## Настройка и адаптеры харнесов

Пакет `harnesses/<имя>/harness.json` определяет команду запуска и необязательную `telemetry_command`. Каждая команда — отдельный процесс; ядро передаёт ей пути через окружение. Адаптер телеметрии получает `BENCH_AGENT_STDOUT`, выводит один JSON-объект на stdout; его ошибки сохраняются в `telemetry/` и не скрывают исходный журнал. Можно добавить новый пакет без изменения ядра.

Параметры конкретного прогона передаются через `--harness-config examples/qwen-config.json`: адаптер получает путь в `BENCH_HARNESS_CONFIG`, а копия параметров сохраняется в результате. Для Qwen Code и Codex поддерживаются `executable`, список `args` и `prompt`. Не помещайте ключи и пароли в этот JSON: файл сохраняется в артефактах; используйте механизмы авторизации самого харнеса. Исполняемые команды и признак модельного запуска задаются в доверенном пакете, а не в параметрах прогона.

Подготовлен пакет `qwen-code`, работающий через документированный headless CLI (`-p`, `--output-format stream-json`). Qwen Code не установлен в текущем окружении, поэтому интеграция проверена с подставной командой, без модели; отдельный адаптер интерпретации телеметрии Qwen ещё не реализован, исходные события сохраняются. Конфигурация модели может передаваться через `args` согласно установленной версии Qwen Code или через её собственные настройки.
